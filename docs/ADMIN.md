# 캐릭터챗 어드민 설계

## 어드민의 핵심 질문

어드민은 운영자가 다음 질문에 바로 답할 수 있어야 합니다.

1. 이 채팅은 어떤 캐릭터와 연결되어 있는가?
2. 정확히 어느 페르소나 버전을 사용하고 있는가?
3. 어떤 기억 정책으로 몇 개의 기억을 불러왔는가?
4. 특정 답변에서 어떤 기억이 왜 선택되었는가?
5. 감도를 바꾸면 실제 검색 결과가 어떻게 달라지는가?

## 화면 구조

### 1. 운영 대시보드

상단 지표:

- 오늘 활성 채팅 수
- 기억 검색 성공률
- 평균 검색 결과 수
- 평균/95백분위 검색 시간
- 기억 미검색 비율
- 사용자 신고 또는 잘못된 기억 비율

최근 경고:

- 유사도 임계값 이하인데 주입된 기억
- 서로 모순되는 기억의 동시 선택
- 지나치게 많은 기억을 사용하는 채팅
- LLM/API 오류와 검색 지연 증가

### 2. 캐릭터 목록

각 행에 다음 정보를 표시합니다.

- 캐릭터 이름과 상태
- 현재 발행 페르소나 버전
- 적용 중인 기억 정책
- 연결된 활성 채팅 수
- 최근 변경자와 변경 시각

### 3. 캐릭터 상세

탭 구성:

- `기본 정보`: 이름, 소개, 이미지, 공개 상태
- `페르소나`: 시스템 프롬프트, 말투·행동·안전 규칙, 버전 비교
- `기억 정책`: 현재 정책과 테스트 도구
- `연결된 채팅`: 채팅 ID, 익명 사용자, 페르소나 버전, 생성일
- `변경 이력`: 발행·롤백·바인딩 변경 감사 로그

### 4. 채팅 상세

헤더에서 연결 관계를 한 줄로 명확하게 보여줍니다.

```text
채팅 conv_123 → 루나 → Persona v3 → Balanced Memory v2
```

본문은 세 영역으로 구성합니다.

- 대화 타임라인
- 선택된 메시지의 기억 검색 결과
- 해당 시점에 사용된 페르소나·정책 스냅샷

기억 결과에는 순위, 최종 점수, 유사도, 중요도, 최근성, 빈도, 출처 메시지와 제외 사유를 표시합니다.

### 5. 기억 감도 실험실

운영자가 실제 메시지를 입력하거나 과거 요청을 불러와 정책 변경 전후를 비교합니다.

```text
현재 정책                  실험 정책
1. 민트초코 선호 0.82      1. 민트초코 선호 0.88
2. 어제 산책 0.51          2. 부산 첫 만남 0.63
3. 부산 첫 만남 0.49       임계값 미달 1건 제외
```

저장 전 반드시 영향을 받는 캐릭터와 예상 검색량 변화를 표시합니다. 정책 변경은 초안 저장→시뮬레이션→발행 순서로 진행합니다.

## 감도 조절 모델

사용자에게 하나의 모호한 “감도” 슬라이더만 제공하면 어떤 값이 바뀌는지 알기 어렵습니다. 어드민에는 고급 설정을 유지하고, 상단에는 다음 프리셋을 제공합니다.

### 보수적

- `minimum_similarity`: 높음
- `top_k`: 2~3
- 오래되거나 중요도가 낮은 기억을 적게 사용
- 잘못된 기억을 말하는 비용이 큰 서비스에 적합

### 균형

- `minimum_similarity`: 중간
- `top_k`: 4~5
- 의미 관련성을 중심으로 중요도와 최근성을 보조 사용
- 기본 캐릭터챗에 권장

### 적극적

- `minimum_similarity`: 낮음
- `top_k`: 6~8
- 오래된 관계 사건도 더 자주 회상
- 풍부한 회상이 중요하지만 엉뚱한 기억 가능성이 증가

### 고급 조절값

| 설정 | 올렸을 때 | 주요 위험 |
|---|---|---|
| 최소 유사도 | 관련성이 확실한 기억만 선택 | 회상 누락 증가 |
| `top_k` | 프롬프트에 기억을 더 많이 삽입 | 비용·잡음·모순 증가 |
| 유사도 가중치 | 현재 질문과 직접 관련된 기억 우선 | 중요하지만 표현이 다른 기억 누락 |
| 중요도 가중치 | 핵심 취향·약속·사건 우선 | 무관한 중요 기억 노출 |
| 최근성 가중치 | 최근 대화 우선 | 오래된 장기 설정 약화 |
| 빈도 가중치 | 반복 확인된 기억 우선 | 자기강화 편향 |
| 반감기 | 오래된 기억을 오래 유지 | 낡은 정보가 남음 |
| assistant 신뢰도 | 캐릭터 발언도 기억으로 적극 사용 | 모델이 만든 오류 재학습 |

프리셋은 여러 고급 값을 동시에 바꾸는 UI일 뿐이며, 서버에는 실제 개별 값과 정책 버전을 저장합니다.

## 권장 초기 정책

```text
candidate_limit = 30
top_k = 5
minimum_similarity = 0.35
similarity = 0.70
importance = 0.15
recency = 0.10
frequency = 0.05
```

이 값은 업계 표준이 아니라 초기 가설입니다. 운영 데이터로 다음 지표를 측정하며 조정합니다.

- `Recall@K`: 정답 기억을 후보에 포함했는가
- `MRR`: 정답 기억이 얼마나 위에 있는가
- `nDCG`: 여러 관련 기억의 순서가 적절한가
- 잘못된 기억 사용률
- 기억이 필요했는데 사용하지 않은 비율
- 사용자 수정·삭제·신고율

## 권한과 안전장치

- `Viewer`: 채팅과 지표 조회, 원문 미열람
- `Analyst`: 익명화된 검색 추적과 시뮬레이션
- `Operator`: 캐릭터·정책 초안 편집
- `Publisher`: 페르소나·정책 발행과 롤백
- `Privacy Admin`: 제한된 원문 열람과 사용자 삭제 처리

원문 열람은 기본 차단하고 사유 입력, 시간 제한 권한, 감사 로그를 요구합니다. 관리자 화면에서 API 키나 전체 시스템 프롬프트가 브라우저 로그에 노출되지 않도록 합니다.

## 구현 순서

1. Character, PersonaVersion, MemoryPolicy, Conversation 테이블 추가
2. `/v1/conversations` 기반 서버 소유 바인딩으로 채팅 API 교체
3. 읽기 전용 캐릭터·채팅·검색 추적 어드민 구현
4. 기억 정책 시뮬레이터 추가
5. 페르소나·정책 버전 발행 및 롤백 추가
6. 역할 기반 권한, 감사 로그, 사용자 데이터 삭제 기능 추가
