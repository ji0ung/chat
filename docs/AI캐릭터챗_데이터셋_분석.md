# AI 캐릭터챗 데이터셋 분석

> 본 문서는 개인 프로젝트에서 사용할 데이터셋을 **무엇을 관찰할 수 있는지 / 무엇을 말할 수 없는지 / 어떤 분석 질문에 적합한지** 기준으로 정리한 자료다.  
> 실제 EDA 결과가 아직 없는 항목은 결과처럼 쓰지 않고, 데이터 구조와 분석 가능 범위만 정리한다.

---

## 1. 데이터셋을 고르는 기준

이번 프로젝트의 핵심 질문은 다음과 같다.

> **AI 캐릭터챗에서 어떤 상호작용 패턴이 더 긴 대화와 함께 나타나는가?**

> **대화가 진행될수록 관계적인 표현은 어떻게 달라지는가?**

> **특정 AI 응답 이후 같은 세션의 대화가 얼마나 더 이어지는가?**

따라서 데이터셋을 고를 때 단순히 데이터가 크다는 이유보다 아래 조건을 우선한다.

1. 실제 사용자와 AI의 다중 턴 대화가 있어야 한다.
2. 사용자와 AI 발화를 구분할 수 있어야 한다.
3. 대화 순서가 보존되어야 한다.
4. 하나의 대화 단위가 구분되어야 한다.
5. 캐릭터 또는 페르소나 정보가 있어야 한다.
6. 대화 길이와 상호작용 패턴을 함께 볼 수 있어야 한다.
7. 공개적으로 사용할 수 있어야 한다.

이 기준에서 **PIPPA를 메인 데이터셋**, RP-Opus를 보조 검증 후보로 둔다.

---

# 2. 메인 데이터셋 — PIPPA

## 2.1 무엇인가

PIPPA는 Character.AI 사용자들이 자발적으로 제공한 실제 캐릭터 대화 로그를 모은 공개 데이터셋이다.

현재 프로젝트 기획 기준으로 확인한 특징은 다음과 같다.

- 약 26,000개 대화
- 100만 줄 이상의 대화 데이터
- 1,000개 이상의 캐릭터 페르소나
- 사용자와 AI 발화 구분 가능
- 다중 턴 대화 순서 보존
- 캐릭터별 대화 비교 가능

출처: https://huggingface.co/datasets/PygmalionAI/PIPPA

---

## 2.2 왜 메인 데이터로 적합한가

PIPPA의 가장 큰 장점은 **한 번의 질문-응답이 아니라 실제로 이어진 대화 흐름을 볼 수 있다는 점**이다.

이 프로젝트에서는 아래처럼 분석할 수 있다.

> 대화 단위  
> → 턴 단위  
> → 사용자·AI 발화  
> → 대화 진행 단계  
> → 다음 턴 지속 여부

즉 단순 텍스트 분류 데이터가 아니라 **대화가 어떻게 이어지는지**를 볼 수 있다.

이 구조는 이번 프로젝트의 핵심인 `대화 지속`과 `관계적 상호작용`을 관찰하기에 적합하다.

---

## 2.3 PIPPA로 직접 관찰할 수 있는 것

### 1) 대화 길이

- 전체 턴 수
- 사용자 턴 수
- AI 턴 수
- 짧은 대화와 긴 대화의 차이

### 2) 대화 진행

- 초반 / 중반 / 후반
- 턴 백분위 기준 진행 단계
- 대화가 길어지면서 표현이 어떻게 변하는지

### 3) 발화 특성

- 메시지 길이
- 질문 여부
- 감정 표현
- 자기노출
- 취향·개인 정보 공유
- 관계를 암시하는 표현
- 과거 대화 맥락 참조
- 별명·호칭
- 다음 대화 또는 미래 상호작용 언급

### 4) 같은 세션 안의 대화 지속

특정 턴 이후:

- 다음 턴이 존재하는가
- 몇 턴이 더 남았는가
- 이후 5턴 이상 이어지는가
- 이후 10턴 이상 이어지는가

를 볼 수 있다.

---

# 3. PIPPA로 말할 수 없는 것

이 부분이 프로젝트에서 가장 중요하다.

## 3.1 대화 지속 ≠ 재방문율

PIPPA에서 볼 수 있는 것은 **한 세션 안에서 대화가 계속됐는지**다.

동일 사용자가 다음 날 또는 다음 주에 다시 서비스에 왔는지는 알 수 없다.

따라서:

> **대화 지속 = 세션 내 행동**

> **재방문율 = 세션 밖 행동**

으로 구분한다.

PIPPA 분석 결과를 D1, D3, D7 재방문율로 표현하지 않는다.

---

## 3.2 긴 대화 ≠ 좋은 관계

대화가 길다고 해서 사용자가 캐릭터를 좋아했다고 단정할 수 없다.

긴 대화가 발생하는 이유는 여러 가지일 수 있다.

- 재미있어서 계속 대화했을 수 있음
- 롤플레잉 특성상 대사가 길었을 수 있음
- 반복 질문이 이어졌을 수 있음
- 불만이나 수정 요구 때문에 길어졌을 수 있음
- 사용자가 실험적으로 대화를 길게 했을 수 있음

따라서 `긴 대화`는 **관계 형성의 결과 지표가 아니라 분석 대상 행동 지표**로 다룬다.

---

## 3.3 관계적 표현 ≠ 실제 관계 형성

예를 들어 “보고 싶었어”, “우리 다음에 또 만나자” 같은 표현이 증가했다고 해도 실제 사용자의 심리적 애착을 직접 측정한 것은 아니다.

따라서 분석에서는:

> **관계가 깊어졌다**

보다

> **관계적 표현이 증가했다**

또는

> **관계적 상호작용 패턴이 관찰됐다**

라고 표현한다.

---

## 3.4 연관성 ≠ 인과관계

예를 들어 과거 맥락을 참조한 AI 응답 뒤에 대화가 더 오래 이어졌다고 해도,

> **과거 맥락 참조가 대화를 길게 만들었다**

고 바로 말할 수 없다.

캐릭터 종류, 대화 주제, 사용자 성향, 이미 길어진 대화였는지 등 다른 요인이 영향을 줄 수 있기 때문이다.

따라서 PIPPA 분석은 기본적으로:

> **특정 상호작용과 대화 지속 사이의 연관성 탐색**

까지 수행한다.

실제 기능 효과는 이후 별도 실험에서 검증한다.

---

# 4. 분석 단위

기본 분석 단위는 **대화(Conversation)**와 **턴(Turn)** 두 개다.

| 분석 단위 | 주요 변수 예시 |
| --- | --- |
| 대화 | conversation_id, character, total_turns |
| 턴 | turn_number, speaker, message, message_length |
| 지속 | next_turn, remaining_turns, 5턴/10턴 지속 |
| 진행 단계 | 초반 / 중반 / 후반, turn_percentile |
| 상호작용 | 질문, 자기노출, 감정 표현, 과거 맥락 참조 |
| 관계 표현 | 관계적 문장, 호칭, 다음 만남·미래 상호작용 언급 |

기본 데이터마트 형태:

```text
conversation_id
character
turn_number
speaker
message
message_length
total_turns
next_turn
remaining_turns
progress_stage
```

이후 분류 결과가 생기면 다음 열을 추가한다.

```text
is_question
self_disclosure
emotional_expression
relational_language
past_context_reference
future_interaction_reference
```

# 5. 핵심 분석 질문별 데이터 적합성

## Q1. 긴 대화와 짧은 대화는 무엇이 다른가?

**PIPPA 적합도: 높음**

가능한 비교:

- 메시지 길이
- 질문 빈도
- 자기노출
- 감정 표현
- 관계적 언어
- 과거 맥락 참조
- 캐릭터별 차이

주의점:

단순히 긴 대화 전체와 짧은 대화 전체를 비교하면 `대화가 길어서 관계적 표현이 많아진 것`과 `관계적 표현이 있어서 대화가 길어진 것`을 구분하기 어렵다.

따라서 **긴 대화의 초반부와 짧은 대화를 비교하는 분석**이 중요하다.

예:

> 긴 대화의 첫 10턴 vs 짧은 대화 전체 또는 첫 10턴

이렇게 보면 긴 대화가 **처음부터 다른 특징을 가졌는지** 확인할 수 있다.

---

## Q2. 대화가 진행되면서 관계적 상호작용은 어떻게 변하는가?

**PIPPA 적합도: 높음**

대화별 길이가 다르기 때문에 단순 턴 번호보다 `진행률`을 함께 사용하는 것이 좋다.

예:

- 초반: 0~33%
- 중반: 34~66%
- 후반: 67~100%

또는 충분히 긴 대화만 대상으로 고정 턴 구간을 비교한다.

여기서 볼 수 있는 것은 **대화 진행에 따른 표현 변화**이지 심리적 관계 깊이를 직접 측정하는 것은 아니다.

---

## Q3. 특정 AI 응답 이후 대화 지속은 어떻게 달라지는가?

**PIPPA 적합도: 중간~높음**

AI 응답마다 다음 지표를 붙일 수 있다.

- 다음 사용자 턴 존재 여부
- 남은 턴 수
- 5턴 이상 지속 여부
- 10턴 이상 지속 여부

예를 들어:

> 과거 맥락을 참조한 AI 응답 이후의 지속률

과

> 그렇지 않은 AI 응답 이후의 지속률

을 비교할 수 있다.

다만 대화 후반부에서는 구조적으로 남은 턴이 적기 때문에 **턴 위치를 반드시 통제하거나 층화**해야 한다.

---

# 6. 관계적 상호작용 분류 초안

초기에는 너무 많은 분류 항목을 만들지 않는다.

우선 다음 정도로 시작한다.

| 분류 | 의미 | 예시 방향 |
| --- | --- | --- |
| 자기노출 | 사용자가 자신에 대한 정보를 공개 | 경험, 고민, 취향 |
| 감정 표현 | 감정 상태를 직접 표현 | 기쁨, 불안, 외로움 |
| 관계적 표현 | 캐릭터와의 관계를 언급 | 좋아함, 친밀감, 신뢰 |
| 과거 맥락 참조 | 이전 발화를 다시 언급 | “아까 네가 말한…” |
| 호칭·관계 명명 | 별명이나 관계를 정의 | 친구, 연인, 선생님 등 |
| 미래 상호작용 | 다음 대화·만남을 언급 | “다음에 또 이야기하자” |

초기 샘플에 사람이 직접 라벨링한 뒤, 필요할 경우 LLM 보조 분류를 사용한다.

LLM 분류를 사용할 경우 반드시 일부 샘플을 사람이 다시 확인해 분류 품질을 검증한다.

# 7. 데이터 품질 및 편향 위험

## 7.1 자발적 제공 데이터라는 점

PIPPA는 사용자가 자발적으로 제공한 대화이므로 Character.AI 전체 사용자를 대표한다고 보기 어렵다.

대화를 공유할 정도로 적극적인 사용자나 특정 롤플레잉 성향 사용자가 더 많이 포함됐을 가능성이 있다.

따라서:

> **Character.AI 전체 사용자 행동을 대표한다**

고 주장하지 않는다.

---

## 7.2 오래된 서비스 시점의 데이터

AI 캐릭터 서비스는 모델·기억·안전 정책이 빠르게 바뀐다.

PIPPA에서 관찰한 패턴은 현재 Character.AI의 최신 제품 품질을 그대로 나타내는 자료가 아니다.

이 데이터의 목적은 **현재 서비스 성과 평가**가 아니라 **캐릭터 대화의 상호작용 구조 탐색**이다.

---

## 7.3 민감·성인 콘텐츠

공개 캐릭터 대화에는 민감하거나 성인 지향 콘텐츠가 포함될 수 있다.

이번 프로젝트 목적에 필요하지 않은 경우:

- 명시적 성적 콘텐츠
- 폭력적 콘텐츠
- 분석에 부적절한 민감 대화

는 제외 기준을 만들고 별도로 기록한다.

제외 후 표본 특성이 어떻게 달라졌는지도 확인한다.

---

## 7.4 캐릭터 편향

특정 인기 캐릭터가 대화 수를 많이 차지하면 전체 결과가 일부 캐릭터 특성에 의해 좌우될 수 있다.

따라서:

- 캐릭터별 대화 수 분포
- 상위 캐릭터 집중도
- 최소 대화 수 기준
- 캐릭터 고정효과 또는 캐릭터별 층화

등을 검토한다.

---

# 8. 보조 데이터셋 — RP-Opus

## 8.1 역할

RP-Opus는 메인 데이터가 아니라 **PIPPA에서 찾은 패턴이 다른 최근 역할극·컴패니언 데이터에서도 나타나는지 확인하는 보조 데이터**로 둔다.

출처: https://huggingface.co/datasets/taozi555/rp-opus

활용 후보:

- 최근 역할극 대화와 비교
- 한국어 하위 데이터 탐색
- PIPPA에서 만든 관계적 상호작용 분류가 다른 데이터에서도 작동하는지 확인

---

## 8.2 왜 처음부터 합치지 않는가

서로 다른 데이터셋을 바로 합치면 다음 문제가 생긴다.

- 서비스·모델이 다름
- 데이터 수집 방식이 다름
- 대화 목적이 다를 수 있음
- 사용자 집단이 다름
- 언어 분포가 다름

따라서 처음부터 하나의 큰 데이터로 합치기보다:

> **PIPPA에서 주 분석 → RP-Opus에서 방향성 재확인**

순서로 사용한다.

---

# 9. 한국어 품질 분석은 별도 트랙

PIPPA의 핵심 목적은 대화 지속과 관계적 상호작용 분석이다.

한국어 자연스러움 문제까지 동시에 해결하려 하면 분석 질문이 너무 넓어진다.

따라서 한국어 캐릭터 말투 문제는 별도 평가셋으로 분리한다.

평가 후보:

- 한국어 구어체 자연스러움
- 번역체·직역투
- 캐릭터 고유 말투
- 존댓말·반말 일관성
- 과도한 설명체
- 감정 상황에 맞는 말 길이
- 캐릭터 설정 일관성

즉:

> **PIPPA = 행동 데이터 분석**

> **한국어 평가셋 = 제품 품질 평가**

로 역할을 나눈다.

# 10. 데이터 분석 순서

## 1단계. 구조 확인

- 실제 컬럼 확인
- 결측치
- 중복 대화
- 사용자·AI 발화 구분
- 대화 ID와 캐릭터 ID 확인
- 민감 콘텐츠 처리 기준

## 2단계. 기본 탐색 분석

- 대화 길이 분포
- 턴 수 분포
- 메시지 길이 분포
- 캐릭터별 대화 수
- 긴 대화·짧은 대화 기준 후보

## 3단계. 긴 대화 vs 짧은 대화

- 전체 차이
- 초반부만 비교
- 캐릭터별 차이

## 4단계. 대화 진행 분석

- 초반 / 중반 / 후반
- 관계적 표현 변화
- 사용자·AI 발화 변화

## 5단계. 턴 단위 지속 분석

- 다음 턴
- 남은 턴 수
- 5턴·10턴 지속
- AI 응답 특징과의 연관성

## 6단계. 제품 가설로 번역

> **데이터에서 관찰된 패턴**  
> → **가능한 제품 문제**  
> → **기술 구조 확인**  
> → **기능 가설**  
> → **별도 평가·실험**

# 11. 분석 결과를 해석할 때 지킬 원칙

- 대화 지속을 재방문율이라고 부르지 않는다.
- 긴 대화를 좋은 관계라고 단정하지 않는다.
- 관계적 표현을 실제 애착과 동일시하지 않는다.
- 공개 대화 데이터의 연관성을 인과관계로 표현하지 않는다.
- PIPPA 사용자를 전체 캐릭터챗 사용자로 일반화하지 않는다.
- 실제 기능 효과는 별도 실험에서 검증한다.
- 데이터가 보여주는 사실과 제품 가설을 문서에서 분리한다.

# 12. 현재 데이터셋 선택 결론

| 데이터 | 역할 | 이번 프로젝트에서의 우선순위 |
| --- | --- | --- |
| PIPPA | 대화 지속·상호작용 패턴 주 분석 | **메인** |
| RP-Opus | 최근 역할극·컴패니언 패턴 재확인 | 보조 |
| 한국어 소규모 평가셋 | 캐릭터 말투·자연스러움 품질 평가 | 후속 |
| 실제 사용자 실험 데이터 | D1/D3/D7 재방문 검증 | 최종 후속 |

현재 단계에서 가장 중요한 것은 데이터셋을 더 많이 모으는 것이 아니다.

> **PIPPA 하나에서 대화 구조를 제대로 이해하고, 무엇을 말할 수 있고 무엇을 말할 수 없는지 명확히 구분하는 것**

이 우선이다.

이후 실제 분석 결과가 생기면 본 문서에 `EDA 결과`, `핵심 발견`, `제품 가설` 섹션을 추가한다.
