# 개인 프로젝트 기획안

## When Does a Chat Become a Relationship?
### AI 캐릭터챗에서 대화 지속과 관계적 상호작용을 만드는 패턴 분석

---

## 1. 프로젝트 포지셔닝

이 프로젝트의 중심은 **스토리 생성 자체가 아니라 AI 캐릭터 / 컴패니언 제품**이다.

스토리챗이 주로 “다음 장면을 보고 싶게 만드는 서사적 몰입”을 다룬다면, 캐릭터챗은 “이 캐릭터와 다음 대화를 계속하고 싶게 만드는 상호작용”을 더 직접적으로 다룬다.

다만 여기서 중요한 전제가 있다.

> **대화가 길다고 해서 관계가 깊다고 볼 수 없고, 관계적 표현이 많다고 해서 실제 재방문이 발생한다고 단정할 수 없다.**

따라서 프로젝트는 다음 단계를 구분한다.

> **사용자 행동 관찰 → 제품 가설 → 기술 구조 확인 → 평가 실험 → 가능하면 사용자 재방문 실험**

1. **사용자 행동 관찰** — 공개 대화 데이터에서 어떤 상호작용이 긴 대화와 함께 나타나는지 분석한다.
2. **제품 가설** — 관찰된 패턴을 제품 문제와 기능 가설로 번역한다.
3. **기술 구조 확인** — 오픈소스 캐릭터챗을 통해 해당 기능이 어떤 구조로 구현되는지 이해한다.
4. **평가 실험** — 핵심 문제 1개를 골라 기본안과 개선안을 비교한다.
5. **사용자 실험** — 가능하면 실제 사용자의 세션 지속 또는 재방문을 별도로 검증한다.

핵심 목표는 완성형 캐릭터챗 서비스를 만드는 것이 아니다.

> **공개 사용자 행동 데이터에서 출발해, 데이터가 말할 수 있는 범위 안에서 제품 문제를 정의하고, 그 문제를 실제 AI 제품 구조와 검증 실험으로 연결하는 것**

이 프로젝트의 목표다.

---

## 2. 왜 AI 캐릭터 / 컴패니언을 선택했는가

### 2.1 관계형 제품 문제를 행동 데이터로 관찰할 수 있다

일반적인 정보 검색형 챗봇은 정확한 답변이나 작업 완료가 주요 가치일 수 있다.

반면 캐릭터챗에서는 사용자가 특정 캐릭터와 여러 턴에 걸쳐 상호작용한다. 따라서 다음과 같은 제품 질문이 중요해진다.

- 왜 어떤 대화는 짧게 끝나고 어떤 대화는 오래 이어지는가?
- 긴 대화에서는 사용자와 AI의 상호작용 방식이 어떻게 다른가?
- 캐릭터 설정, 기억, 말투, 과거 맥락 참조는 대화 경험과 어떤 관련이 있는가?
- 사용자가 다시 대화하고 싶다고 느끼는 데 어떤 요소가 영향을 줄 수 있는가?

여기서 바로

> **대화 지속 → 관계 형성 → 재방문 → 수익화**

이라고 인과관계를 가정하지 않는다.

대신 각 단계를 따로 본다.

> **세션 내 대화 지속**  
> → 관계적 상호작용과의 **연관성 확인**  
> → 제품 기능 가설  
> → 실제 재방문·결제는 별도 데이터나 실험으로 검증

이렇게 나누면 공개 데이터가 말할 수 있는 것과 실제 제품 성과를 구분할 수 있다.

### 2.2 실제 AI 제품의 핵심 문제와 연결할 수 있다

캐릭터챗은 단순히 LLM API를 연결한다고 완성되지 않는다.

실제 제품에서는 다음 문제가 중요하다.

- 캐릭터 설정 일관성
- 대화 맥락 유지
- 장기 기억
- 필요한 기억 검색·호출
- 캐릭터 고유 말투
- 자연스러운 한국어
- 응답 속도·비용·품질의 균형
- 관계 단계와 상황에 맞는 반응

따라서 데이터 분석 이후에도

> **관찰된 행동 패턴 → 제품 문제 → 실제 구현 구조 → 평가 실험**

으로 연결하기 좋다.

### 2.3 공개 데이터와 실제 제품 실험의 역할을 분리할 수 있다

PIPPA와 같은 공개 대화 데이터에서는 세션 안에서의 대화 지속과 상호작용 패턴을 분석할 수 있다.

반면 다음은 알 수 없다.

- 동일 사용자가 다음날 다시 왔는가
- 실제 D1 / D7 재방문율이 얼마인가
- 특정 기능이 재방문을 높였는가
- 결제 의향 또는 실제 결제가 증가했는가

따라서 이 프로젝트는 하나의 데이터셋으로 모든 것을 설명하려 하지 않는다.

> **공개 데이터 관찰 분석 → 제품 가설 → 검증용 평가 → 사용자 실험**

으로 단계를 나눈다.

## 3. AI 컴패니언 시장 배경

> 시장 조사는 “이 프로젝트의 분석 결과를 증명하는 자료”가 아니라, **왜 이 문제를 볼 가치가 있는지 설명하는 배경**으로 사용한다.

### 3.1 시장 규모 숫자는 직접 비교하지 않는다

AI 컴패니언 시장은 조사기관마다 포함 범위가 다르다.

예를 들어 일부 조사기관은 AI 친구, 가상 인간, 상담·생활 보조 등 넓은 범위를 포함하기 때문에 시장 규모가 크게 잡힌다.

Grand View Research는 글로벌 AI Companion 시장을 2025년 약 **368억 달러**, 2026년 약 **480억 달러**로 추정하고, 2033년 약 **3,180억 달러**까지 성장할 것으로 전망한다.

Source: https://www.grandviewresearch.com/industry-analysis/ai-companion-market-report

이 수치는 **캐릭터챗 모바일 앱 매출과 같은 의미가 아니다.**

따라서 본 프로젝트에서는 이 숫자를 직접적인 시장 크기 증명보다 **넓은 AI 컴패니언 범주의 성장 전망 참고치**로만 사용한다.

### 3.2 더 직접적인 신호는 실제 서비스 규모와 사용량이다

Character.AI는 2025년 자사 기술 블로그에서 **월간 활성 사용자 2,000만 명 이상**을 지원한다고 밝혔다.

Source: https://blog.character.ai/harnessing-data-at-scale-character-ais-transition-to-warpstream/

앱 소비 측면에서도 여러 국가에서 AI 컴패니언 앱 지출이 발생하고 있다.

Source: https://www.statista.com/statistics/1607445/top-markets-for-ai-companion-apps/

이런 자료는 “모든 컴패니언 서비스가 성공한다”는 증거가 아니다.

다만 다음을 보여주는 시장 신호로 사용한다.

- 실제 사용자 규모가 큰 서비스가 존재한다.
- 반복 대화형 AI에 소비가 발생한다.
- 국가별로 다른 시장 수요가 나타난다.

### 3.3 국내 시장도 실제 서비스 지표를 중심으로 본다

Grand View Research는 한국 AI Companion 시장을 2025년 약 **10.66억 달러**, 2033년 약 **81.10억 달러**로 전망한다.

Source: https://www.grandviewresearch.com/horizon/outlook/ai-companion-market/south-korea

이 역시 범위가 넓은 시장 추정치이므로 직접적인 캐릭터챗 시장 규모로 사용하지 않는다.

국내에서 더 직접적인 신호는 실제 캐릭터챗 서비스의 성장이다.

2026년 서울경제 보도에 따르면:

- Scatter Lab의 **Zeta**는 누적 가입자 약 600만 명
- 2026년 5월 기준 국내 월간 이용자 약 **140만 명**
- 일본 주간 사용자 약 **75만 명**
- 일본 사용자의 평균 일일 사용시간 약 **4시간**
- Scatter Lab은 전년도 매출 약 **260억 원**, 영업이익 약 **30억 원** 기록
- Wrtn의 **Crack**은 2026년 5월 월간 이용자 약 **55만 명**
- Wrtn은 일본과 미국으로 캐릭터챗 서비스를 확장 중

Source: https://en.sedaily.com/technology/2026/06/14/ai-chat-app-zeta-drives-scatter-lab-to-50-billion-won

네이버웹툰 역시 작품 속 캐릭터와 대화할 수 있는 캐릭터챗 서비스를 운영하고, 메시지 구매 구조를 제공한다.

Source: https://help.naver.com/service/5635/contents/23251?lang=ko&osType=MOBILE

Crack은 사용자 생성 캐릭터와 창작자 구조를 운영하며, 창작자 조건에 캐릭터 수, 대화 사용자 수, 팔로워 수, 누적 발화 수 등을 사용한다.

Source: https://help.crack.wrtn.ai/guide/creator/info/how-to-become

여기서 말할 수 있는 것은 다음 정도다.

> **국내에서도 캐릭터챗이 단순 기능 실험을 넘어 실제 이용자 규모·콘텐츠 공급·수익화 구조를 가진 제품군으로 발전하고 있다.**

### 3.4 시장 구조

| 유형 | 핵심 가치 | 주요 제품 문제 | 수익화 후보 |
| --- | --- | --- | --- |
| 캐릭터 컴패니언 | 특정 캐릭터와의 관계·대화 | 설정 일관성, 기억, 말투 | 구독, 메시지, 고급 모델 |
| IP 컴패니언 | 기존 IP 캐릭터와 상호작용 | 원작 설정 일관성, IP 안전성 | 메시지, IP 소비, 굿즈 연계 |
| 팬덤 컴패니언 | 팬덤 기반 반복 상호작용 | 개인화, 희소성 | 멤버십, 굿즈, 디지털 재화 |
| 스토리·롤플레잉 | 서사 몰입과 다음 전개 | 줄거리, 분기, 전개 속도 | 메시지, 유료 스토리 |
| 생활형 컴패니언 | 친구·생활 파트너형 대화 | 개인화, 기억 | 구독, 유료 기능 |

본 프로젝트는 이 중 **캐릭터 / 컴패니언의 관계적 상호작용과 세션 내 대화 지속**에 집중한다.

### 3.5 이 프로젝트가 보는 시장 질문

시장 규모 자체보다 다음 질문에 관심이 있다.

> **캐릭터챗 경쟁이 단순 모델 성능 경쟁을 넘어, 기억·캐릭터 설정·말투·관계 연속성 같은 제품 품질 경쟁으로 이동하고 있는가?**

이 역시 시장 자료만으로 결론내리지 않는다.

시장 사례는 배경으로 보고, 실제 프로젝트에서는 공개 대화 데이터와 오픈소스 구조 분석으로 좁혀서 확인한다.

## 4. 핵심 문제 정의

AI 캐릭터챗에서 **대화 길이 = 좋은 경험**이라고 볼 수 없다.

같은 30턴의 대화라도:

- 단순 롤플레잉이 반복될 수 있다.
- 질문과 답변만 기계적으로 이어질 수 있다.
- 사용자가 점차 개인적인 이야기를 꺼낼 수 있다.
- 관계를 암시하는 표현이 증가할 수 있다.
- 캐릭터가 과거 대화 맥락을 참조할 수 있다.
- 대화는 길지만 번역체·AI 말투 때문에 몰입이 낮을 수 있다.

따라서 이 프로젝트는 두 종류의 지표를 분리한다.

### 행동 지표
- 전체 턴 수
- 다음 턴 지속 여부
- 남은 턴 수
- 이후 5턴 / 10턴 지속 여부

### 관계적 상호작용 지표
- 자기노출
- 감정 표현
- 개인 취향 공유
- 관계를 나타내는 표현
- 과거 맥락 참조
- 호칭·관계 명명
- 미래 대화 언급

핵심 분석 질문은 다음과 같다.

> **긴 대화와 짧은 대화는 어떤 상호작용 구조 차이를 보이는가?**

> **대화가 진행되면서 관계적 상호작용 패턴은 어떻게 달라지는가?**

> **특정 AI 응답 패턴 이후 세션 내 대화 지속은 어떻게 달라지는가?**

## 5. 데이터로 답할 질문

### Q1. 긴 대화와 짧은 대화는 어떤 차이가 있는가?

분석 후보:

- 사용자 / AI 메시지 길이
- 질문 빈도
- 자기노출
- 감정 표현
- 개인 취향 공유
- 관계적 표현
- 캐릭터별 차이

핵심은 **긴 대화가 처음부터 다른지, 아니면 진행되면서 다른 상호작용이 나타나는지** 확인하는 것이다.

### Q2. 대화가 진행되면서 관계적 상호작용은 어떻게 변화하는가?

초기 분류 기준 후보:

- 자기노출
- 감정 표현
- 관계적 표현
- 개인 취향 공유
- 과거 맥락 참조
- 호칭·관계 명명
- 미래 상호작용 언급

이를 초반 / 중반 / 후반 또는 전체 턴 대비 상대 위치로 비교한다.

단, 실제 “관계가 깊어졌다”고 단정하지 않고 **관계적 상호작용 패턴이 변했다**고 표현한다.

### Q3. 특정 AI 응답 이후 세션 내 대화 지속은 어떻게 달라지는가?

관찰 지표:

- 다음 턴 여부
- 남은 턴 수
- 이후 5턴 지속 여부
- 이후 10턴 지속 여부
- 사용자 메시지 길이 변화

여기서는 인과관계가 아니라 **연관성**만 분석한다.

## 6. 데이터로 알 수 없는 것

PIPPA만으로는 실제 **D1 / D7 재방문율**을 알 수 없다.

동일 사용자가 다음날 다시 서비스에 방문했는지 추적할 수 없기 때문이다.

따라서:

> **세션 내 대화 지속 ≠ 재방문율**

로 구분한다.

또한 공개 대화 데이터만으로 다음을 주장하지 않는다.

- 기억 기능을 넣으면 재방문율이 오른다.
- 관계적 표현이 많으면 사용자가 더 애착을 느낀다.
- 특정 AI 응답이 대화를 길게 만든 원인이다.
- 긴 대화가 곧 높은 만족도를 의미한다.

데이터 분석에서는:

> **“특정 상호작용 패턴과 긴 대화 사이에 연관성이 관찰되었다.”**

까지 말하고, 그 다음 단계부터는 제품 가설 또는 별도 실험으로 분리한다.

## 8. 분석 단위와 데이터마트

기본 분석 단위는 **대화(Conversation)**와 **턴(Turn)**이다.

| 분석 단위 | 예시 변수 |
| --- | --- |
| 대화 | conversation_id, character_id/name, total_turns |
| 턴 | turn_number, speaker, message, message_length |
| 지속 | next_turn, remaining_turns, 5/10-turn continuation |
| 진행 단계 | 초반 / 중반 / 후반, turn percentile |

1차 데이터마트 예시:

`conversation_id | character | turn_number | speaker | message | message_length | total_turns | next_turn | remaining_turns`

## 9. 분석 방법

방법론을 먼저 정하고 데이터를 끼워 맞추지 않는다.

### 1단계 — 데이터 구조 확인과 탐색 분석

- 대화 길이 분포
- 턴 수 분포
- 사용자 / AI 메시지 길이
- 캐릭터별 대화 수
- 짧은 대화 vs 긴 대화 비교
- 민감 콘텐츠 / 제외 기준 확인

### 2단계 — 턴 단위 대화 지속

- 다음 턴 여부
- 남은 턴 수
- 이후 5턴 / 10턴 지속 여부
- 사용자 참여 강도 변화

### 3단계 — 대화 진행에 따른 변화

- 초반 / 중반 / 후반 비교
- 상호작용 패턴 변화

### 4단계 — 관계적 상호작용 분석

- 분류 기준 정의
- 표본 수작업 라벨링
- 필요 시 LLM 보조 분류 + 사람 검증

### 5단계 — 제품 문제로 번역

> **데이터 발견 → 제품 문제 → 기술 구조 → 기능 가설 → 평가 후보**

분석 도구 후보:

- SQL
- Python / pandas
- 통계 검정
- 필요 시 생존분석
- 필요 시 순서 패턴 / 군집 분석
- 시각화

분석의 목표는 복잡한 모델을 사용하는 것이 아니라 **제품 의사결정에 의미 있는 패턴을 찾는 것**이다.

## 10. AI 제품 구조 이해 — 오픈소스 캐릭터챗 분석

완성형 캐릭터챗 개발이 아니라 공개 오픈소스를 통해 실제 구조를 이해한다.

분석 후보:

- RisuAI
- SillyTavern
- a16z Companion App
- OpenPersona

모든 프로젝트를 동일한 깊이로 보지 않고 1~2개를 메인으로 본다.

확인할 질문:

1. 캐릭터 설정은 어떻게 정의·주입되는가?
2. 대화 맥락은 어떻게 유지되는가?
3. 장기 기억은 무엇을 저장하는가?
4. 관련 기억은 언제 불러오는가?
5. 캐릭터 설정 일관성은 어떻게 유지하는가?
6. 긴 맥락의 한계는 어떻게 처리하는가?
7. 캐릭터 말투는 어떻게 제어하는가?
8. 품질·응답속도·비용 사이의 균형은 어떻게 잡는가?

산출물:

- 캐릭터챗 시스템 구조도
- 캐릭터 설정 / 프롬프트 / 대화 맥락 / 기억 / 검색 구조 비교
- 데이터 발견 ↔ 기술 구조 연결표

## 11. 제품 가설로 번역하는 원칙

데이터에서 나온 연관성을 바로 기능 효과로 바꾸지 않는다.

예를 들어:

> **관찰:** 과거 맥락을 참조한 대화에서 더 긴 대화가 관찰됨  
> **해석 후보:** 관계 연속성이 긴 대화와 관련 있을 수 있음  
> **제품 문제 후보:** 사용자가 ‘앞 대화를 기억하지 못한다’고 느끼는 문제가 중요한가?  
> **기능 가설:** 관계 기억을 더 잘 불러오면 경험 품질이 개선될 수 있음  
> **검증:** 기억 기능 기본안 vs 개선안 평가

또는:

> **관찰:** 특정 캐릭터군에서 상대적으로 긴 대화가 관찰됨  
> **해석 후보:** 말투·설정 일관성이 관련 있을 수 있음  
> **기능 가설:** 캐릭터 고유 말투와 설정 유지 강화  
> **검증:** 프롬프트·예시 대화·스타일 제약 비교

이 구조를 통해 **데이터 발견 → 인과 주장**으로 바로 뛰는 것을 막는다.

## 12. 선택형 프로토타입 / 평가

메인 분석 결과에서 가장 중요한 문제 **1개만** 선택한다.

후보:

- 관계 기억
- 캐릭터 말투 / 자연스러운 한국어
- 캐릭터 설정 일관성
- 과거 맥락 참조

실험 구조:

> **문제 정의 → 성공·실패 기준 → 테스트셋 → 기본안 vs 개선안 → 실패 분석 → 제품 판단**

예: 캐릭터 말투

**기본안**
- 기본 캐릭터 설정 프롬프트

**개선안**
- 한국어 구어체 규칙
- 캐릭터별 말투 규칙
- 예시 대화
- 번역체 방지 지침

**평가 항목**
- 한국어 자연스러움
- 번역체 여부
- 캐릭터성
- 설정 일관성
- 문맥 적합성
- 다시 대화하고 싶은 정도

완성형 앱이 아니라 **검증용 실험 환경**을 만드는 것이 목표다.

## 13. 선택형 사용자 실험 — 실제 재방문 검증

실제 재방문을 검증하려면 동일 사용자의 행동을 직접 추적해야 한다.

예시:

**Day 0**
- 캐릭터챗 첫 사용

**D1 / D3 / D7**
- 재방문 여부 확인

비교 후보:

- 기본 캐릭터
- 기억 / 캐릭터 말투 개선안

측정 후보:

- 세션 턴 수
- 세션 길이
- D1 재방문
- D3 / D7 재방문
- 다시 대화할 의향
- 캐릭터 선호 / 애착

사용자 수가 충분하지 않으면 **탐색적 실험**으로만 해석한다.

## 14. 한국어 캐릭터 말투 문제

별도 제품 품질 트랙으로 둔다.

핵심 문제:

> **문법적으로 틀리지는 않지만 번역체·설명체·AI 말투 때문에 인간 또는 캐릭터처럼 느껴지지 않는 문제**

실패 유형 후보:

- 직역투
- 과도한 완전문
- 부자연스러운 대명사 사용
- 한국인이 잘 쓰지 않는 표현
- 과도한 설명
- 캐릭터 간 말투 동질화
- 설정과 다른 존댓말 / 반말
- 감정 상황과 맞지 않는 문장 길이

PIPPA 메인 데이터 분석과 분리해 한국어 평가 트랙으로 다룬다.

## 15. 스토리챗과의 차이

스토리챗은 이번 프로젝트의 메인이 아니다.

| 캐릭터 / 컴패니언 | 스토리챗 |
| --- | --- |
| 관계 지속 | 서사 몰입 |
| 왜 다시 말하고 싶은가 | 왜 다음 장면을 보고 싶은가 |
| 기억 | 서사 구조 |
| 캐릭터 설정 | 세계관 |
| 캐릭터 말투 | 줄거리·전개 속도 |
| 관계 연속성 | 이야기 진행 |

다만 이 표는 두 시장이 완전히 분리되어 있다는 뜻이 아니다.

실제 제품에서는 캐릭터에서 스토리로, 스토리에서 캐릭터 중심 경험으로 확장되는 사례가 존재한다.

따라서 본 프로젝트에서는 **초기 분석 단위를 캐릭터 관계형 상호작용에 좁히기 위해 캐릭터챗을 선택한다.**

스토리챗과의 확장 관계는 별도 시장·전략 문서에서 다룬다.

- 오픈소스 분석은 구조 이해가 목적이며 완성형 서비스를 만들지 않는다.

- 스토리챗은 후속 비교 대상으로 둔다.

## 19. 프로젝트 완료 기준

1차 완료 기준:

1. 재현 가능한 대화-턴 데이터마트가 있다.
2. 최소 1개의 명확한 세션 내 대화 지속 / 참여 패턴을 설명할 수 있다.
3. 관계적 상호작용과 단순 대화 길이를 구분해 해석한다.
4. 분석 결과를 최소 1개의 제품 문제로 번역한다.
5. 해당 제품 문제가 실제 캐릭터챗 구조의 어떤 기능과 연결되는지 설명한다.
6. 데이터가 말하는 것과 해석·가설을 구분한다.
7. 최종 사례 연구에서 **문제 정의 → 데이터 분석 → 해석 → 제품 가설 → 제품 판단** 흐름이 보인다.

이 기준을 충족한 뒤에만 추가 데이터, 스토리챗 비교, 프로토타입 또는 재방문 실험으로 확장한다.
